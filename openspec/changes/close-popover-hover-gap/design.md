## Context

`_wireEvents`（`src/managers/CardOverlayManager.ts:185-188`）は、ホバー対応デバイスで情報アイコンに`mouseenter`/`mouseleave`を貼り、ポップオーバーの開閉を制御している。ポップオーバー自体にはホバーイベントが一切ない。

現在のCSS（`src/ui/styles.ts`）は次の通り:

```
.ghosts-icon-btn { top: 0.375rem; height: 2rem; ... }   // 下端 = 2.375rem
.ghosts-popover  { top: 2.625rem; ... }                  // 上端 = 2.625rem
```

アイコン下端とポップオーバー上端の間に約0.25rem（4px）の隙間があり、アイコンからポップオーバーへカーソルを移動する際にこの隙間を通過すると、アイコンの`mouseleave`が発火して`close()`が呼ばれてしまう。

## Goals / Non-Goals

**Goals:**
- ホバーで開いたポップオーバーへ、マウスで実際に到達・操作できるようにする。

**Non-Goals:**
- クリック/タップでの開閉挙動の変更。
- ポップオーバーの内容・デザイン自体の変更。
- ホバー起点の表示自体を廃止すること（Issue本文にはクリックオンリー化の提案もあったが、まずは隙間を埋める方向で対応し、それで解決しない場合に再検討する）。

## Decisions

### 1. まずはポップオーバーの`top`オフセットを詰めて隙間をゼロにする

`.ghosts-popover`の`top`を`2.625rem`から、アイコンの下端に一致する`2.375rem`に変更する。アイコンとポップオーバーの境界が接していれば、カーソルがその境界を跨ぐ瞬間にアイコンの`mouseleave`とポップオーバー側の判定（境界に接している限り「無人地帯」がない）がほぼ同時に切り替わり、閉じることなく移動できるはずである。

CSSだけの変更で完結し、既存のイベント配線・spec（ホバーで開く、アイコン以外では開かない）を変えずに済むため、まずこれで実機確認する。

### 2. 実機確認の結果次第で、ポップオーバー側にもhover listenerを追加する

隙間ゼロだけでは、境界付近での挙動が環境依存で不安定になる可能性がある（角丸のborder-radiusによる見た目上の境界と実際のボックスの境界のズレ、高速なマウス移動時のブラウザの座標サンプリング等）。実機で問題が残るようであれば、ポップオーバー自体にも`mouseenter`/`mouseleave`を貼り、「アイコンかポップオーバーのどちらかにカーソルがある間は開いたまま」という状態管理に切り替える。

このdesignでは具体的な実装を先に固定せず、1を試した実機確認の結果を見てから2の要否を判断する。

## Risks / Trade-offs

- [Risk] 隙間をゼロにしても、カーソルの動かし方（斜めに素早く動かす等）によっては引き続き稀に閉じてしまう可能性がある → 実機で確認し、必要なら決定2（ポップオーバー側のhover listener追加）で補強する。
